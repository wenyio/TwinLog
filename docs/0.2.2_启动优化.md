# 0.2.2 启动优化

验证日期：2026-11-18。

## 变化

- 串口枚举在启动时立即开始，不等待配置、历史记录或 ADB。
- 配置加载后，历史扫描与 Android 设备枚举并行执行，结果分别显示；历史扫描失败不再跳过设备枚举，ADB 慢时不再阻挡串口列表更新。
- 历史查询增加请求顺序与组件存活检查，防止启动扫描迟到后覆盖用户刚切换目录的记录。
- 版本统一为 0.2.2，继续使用现有生产构建与 WebView2 安装策略。

## 自动验证

- `npm.cmd run build` 通过。
- 新增 `npm.cmd run test:startup`，针对生产前端资源，使用可手动释放的模拟桥接请求验证，无基于机器性能的时间阈值：配置等待时串口可用，历史等待时设备可用，ADB 等待时串口与历史可用，各查询失败互不阻挡，以及新目录结果不被迟到的启动查询覆盖。七种场景通过。
- `npm.cmd run test:capture`、`npm.cmd run test:scroll` 通过，覆盖已有抓取、备注、历史查看与滚动行为。
- `go vet ./...` 通过。
- 根目录 `go test ./...` 与隔离正式构建脚本内的 `go test ./...` 均通过。

## 正式构建

- 使用项目本地 Go 1.27.4 和 Wails v2.17.1。
- `build/bin/TwinLog.exe` 被旧进程占用，在 `.tools/release-0.2.2-startup` 运行 `build.ps1`；首次因缺少 Go 嵌入资源失败，补入当前生产前端资源后重跑成功，Wails 随后完整重建了前端。
- 构建相关源码、前端配置与版本资源和主目录逐一哈希核对一致。
- 交付为 `build/bin/TwinLog-0.2.2.exe`，FileVersion 与 ProductVersion 均为 0.2.2，标准路径的旧 exe 未被覆盖。

## 范围与待验证

- 这次改善从界面加载到列表可用的等待关系，没有修改历史扫描算法或 Wails/WebView2 初始化流程。
- 尚未测量原生窗口首屏冷启动/热启动的耗时，不能将模拟桥接测试结果视为整机启动速度提升数值。
- 未验证真实 MCU / Android 设备连接、热插拔与长时间运行。
