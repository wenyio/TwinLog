# 0.1.1 共享 UID 应用过滤修复

2026-11-17。首版仅使用 UID 过滤并拒绝共享 UID，导致 P19 的 com.unifou.activity 无法选择。已改为共享 UID 使用包名对应进程 PID 过滤；full/android.log 始终保存完整 logcat stdout。

- 按进程 NAME 精确匹配包名、包名:子进程，不按日志正文搜索包名。
- 初始进程快照 + 每 500ms 更新；只采信当前 system_server 发出的 ActivityManager/am_proc_start/am_proc_died 启停记录。
- 应用未运行显示等待；查询进程信息失败明确报错，不退化为抓取整个系统 UID。
- 普通非共享 UID 保留原 UID 筛选。
- PID 轮询/系统事件有时延，短命进程、已退出历史进程和自定义非包名前缀进程可能不在派生应用文件中；原始 full 可作为补查依据。

验证：11 项后台自动测试通过，新增共享 UID 识别、进程边界匹配、同 UID 其他应用排除、PID 刷新/重启/死亡事件。前端生产构建及 go vet 通过。

只读实机验证：ADB serial 5052053488072404，P19；读取应用 UID=1000 且确认为共享 UID，查询当时目标应用进程数为 0；读取全量 logcat 片段 25,495 字节，full 输出逐字节一致，应用过滤为空，符合当时进程状态。未启动、强停应用，未清缓存，未打开串口。实际重启跟随已用模拟数据验证，尚未在该设备主动复现。

使用 build/bin/TwinLog-0.1.1.exe。旧 TwinLog.exe 如果仍在运行，请正常退出后运行新版；避免强制结束正在采集的实例。
