# 串口与 Android 日志采集工具：最小方案

日期：2026-11-17。本文按最新要求收敛：Windows 优先，只保留标题和文本备注，不用数据库，不采用 C#/.NET、C/C++ 技术栈。只评估采集工具，不分析用例问题。

## 1. 使用流程

1. 选择串口、波特率、Android 设备和保存目录，点击“连接”。
2. 工具立即持续保存两路完整日志。
3. 选择要抓取的 Android 应用（也可选“全部应用”），输入标题，点击 Start；复现问题，随时输入或修改备注。
4. 点击 Stop，在“抓取时间_title”目录内保存 mcu.log、android.log 和 notes.txt。
5. 输入下一标题继续抓取；结束时选择多条记录，一键导出 ZIP。

Stop 只停止当前抓取，完整日志一直保存到断开连接。一次只抓一条记录。备注只有一个多行文本框，自动保存，停止后也能修改。

## 2. 第一版功能

| 功能 | 最小实现 |
| --- | --- |
| 连接 | 一个串口 + 一台 Android；串口参数可配置，Android 明确选择设备 |
| Android 应用选择 | 列出应用包名，支持搜索和手动输入包名，也可选择“全部应用”；所选应用用于 Android 预览及当前抓取文件，full 不过滤 |
| 抓取 | 标题必填；Start/Stop；同名记录自动分目录，避免覆盖 |
| 备注 | 一个普通多行文本框；输入后自动保存，切换记录和退出时补充保存 |
| 查看 | MCU、Android 两个滚动预览；暂停滚动和清屏不影响文件保存 |
| 串口时间戳 | 默认逐行添加 `[yyyy-MM-dd HH:mm:ss.fff] `，预览、full/mcu.log 和抓取目录 mcu.log 一致 |
| 完整日志 | 从连接到断开持续保存，不受用例 Start/Stop 影响 |
| 历史 | 列出保存目录里的记录，可查看、改备注、打开文件夹 |
| 导出 | 勾选记录打 ZIP；可选附带本次连接的完整日志 |
| 异常 | 端口占用、ADB 未授权/断线、磁盘写入失败明确提示；保留已保存文件 |

不增加用例编号、现象、测试员、结果状态，不做时间线备注、全文索引、自动分析、多设备并行或复杂回溯。第一版断线后提示手动重连，重连另建连接目录。

## 3. 不用数据库：文件夹 + 少量 JSON

完全可以。日志是顺序文件，标题与备注数量少，第一版无需数据库。

文件组织：每次连接一个目录，标题放在抓取目录名里，内部文件名固定。

```text
本次连接目录/
  full/
    mcu.log
    android.log        # 全部可访问的 adb logcat 输出，不按应用过滤
  抓取时间_title/
    mcu.log
    android.log        # 所选应用的日志；选“全部应用”则保存该范围全部日志
    notes.txt
    record.json
```

record.json 只保存程序需要的标题、开始/结束时间、所选应用包名（或全部）及是否正常结束，不增加用户填写项。连接目录保存一份串口参数和 Android 设备信息。上次使用的配置保存在 settings.json。历史列表扫描这些小 JSON 文件即可，不扫描日志正文。

抓取目录例如 `20261117_143025_123_CDCVM_001`：时间精确到毫秒，标题中的 Windows 非法字符替换、过长部分截短，仍重名时追加序号。record.json 保留完整原标题。第一版 Start 后锁定标题，备注继续可编辑，避免采集中改目录名。导出保留抓取目录，避免不同记录的同名日志互相覆盖。JSON 和备注用临时文件写完后替换，降低写一半损坏的概率。重新启动时，未正常结束的记录标为中断，已经写入的日志可以直接打开。

## 4. 已确定技术

**Go + Wails + React + TypeScript，直接调用官方 adb，不使用数据库。**

| 部分 | 选择 |
| --- | --- |
| 桌面窗口 | Wails |
| 界面 | React + TypeScript |
| 后台采集 | Go；go.bug.st/serial 读取串口，os/exec 启动 adb 子进程 |
| 保存与打包 | Go 标准库文件 I/O、encoding/json、archive/zip |
| Windows 运行条件 | USB/ADB 驱动、设备调试授权、WebView2 Runtime |

这是一个本地桌面程序：React 负责界面，Go 负责串口、ADB、写盘和导出，双方通过 Wails 的本地调用与事件通信，不需要额外部署服务器或 HTTP 服务。

开发环境使用 Go、Node.js 和 Wails 工具链；用户使用打包后的程序，不需要安装 Go 或 Node.js。Windows 需要 WebView2 Runtime、ADB 和设备驱动。第一版只验证 Windows，后续再按需要适配其他平台。

第一版用独立读取 goroutine 和受锁保护的缓冲文件写入实现两路采集，不设置无限接收队列。日志由 Go 直接写盘（MCU 添加行首时间戳，Android full 保留 logcat 输出），只把受限的预览批次和状态传给 React。

## 5. 大日志的最小实现

- 连接后，两路采集器持续按块读取、写入 full 日志，不经过界面复制。
- Start 后，MCU 数据额外写入当前抓取文件；Android 数据按所选应用过滤后写入当前抓取文件。Stop 后关闭当前抓取文件，full 继续写，始终不受应用过滤影响。
- 这比维护偏移索引和事后切片简单。代价是抓取期间日志保存两份：总占用约为完整日志大小加全部抓取日志大小。
- Start/Stop 由各路写入器按顺序处理并确认，不能用界面显示到哪一行判断边界；Stop 完成后，边界前已经收到的数据应已写入对应文件。
- 界面只保留最近约 2000 行，同时限制预览总字节数，批量刷新；超长单行只截断预览，文件保留全部。
- 原始日志不通过前端传输，不整体读入内存；导出流式打包，在后台执行。首版导出已停止的抓取；附完整日志时先断开连接，避免打包活动文件。
- 磁盘写入错误时明确提示并停止会话；读取和文件写入同步推进，磁盘长期阻塞可能造成上游丢失，不能保证任意环境下零丢失。
- 周期刷新文件缓冲；进程异常退出后可能损失尚未写盘的尾部，不能承诺断电零丢失。

MCU .log 默认在每行前添加主机接收时间戳，格式如下，full 和当前抓取共用同一次时间戳处理结果：

```text
[2026-11-17 11:56:10.745] EMV subCmd=33
[2026-11-17 11:56:10.745] set tParam.TerminalType:22
[2026-11-17 11:56:10.745]
[2026-11-17 11:56:10.839] CL_EnhanceReaderCap::00000000
```

时间取电脑收到该行首字节所在数据块的本地时间，精确显示到毫秒；当前实验室为 Asia/Shanghai，连接信息记录时区。它是主机接收时间，不是 MCU 内部事件时间；同一接收块中的多行可以有相同时间戳。

空行也加时间戳；跨接收块的同一行只添加一次，CRLF 作为一个换行处理，同时兼容单独 CR/LF。内容增量写盘，不等整行收齐才保存，避免无换行或超长行积压。Stop/断开时保存已收到但未换行的尾部；若 Start 落在半行中，抓取文件为该片段补行首时间戳，完整日志仍连续保存。第一版不另存原始串口字节文件，日志正文保留收到的字节，只插入时间戳，预览解码独立处理。

full/android.log 原样保存全量 logcat 输出；抓取目录的 android.log 保存匹配应用的记录，保留原日志字段，不再额外添加串口格式的时间戳。首版不需要大文件全文搜索和复杂日志数据库。

Android 使用一条不按应用过滤的 logcat 流（显式选择可访问的全部缓冲区、全部级别），先保存 full，再由 Go 后台派生应用预览和抓取文件。应用按包名选择，不能用日志正文包含包名判断，也不能只在 Start 时取一次 PID。首版通过 logcat UID 与包 UID 匹配，覆盖 App 重启和同 UID 普通多进程；共享 UID 改为按包名识别主进程及“包名:子进程”，结合每 500ms 进程表刷新和系统启停记录更新 PID。应用未运行时显示等待。隔离 UID、自定义非包名前缀进程及无法归属的历史 PID 不属于本次过滤范围，相关上下文仍保存在 full。第一版需在实际 P19 上验证可用字段和识别方式，不能声称完全复刻 Android Studio。

Start 后锁定本次抓取的应用选择，Stop 后可切换；应用未运行时显示“等待应用启动”，full 仍正常保存。无法取得必要进程信息时明确显示过滤异常，不能将空文件误报为成功。ADB 错误输出用于连接诊断，不混入设备日志。

## 6. 完整与同步的边界

串口只能保存成功打开后实际收到的数据。Android 可读取当前仍保留且有权限访问的日志缓存，并继续接收新日志；不能恢复已覆盖的内容。连接时默认不清空 Android 缓存。

Start/Stop 是一次操作控制两路抓取，不代表两台设备事件时间严格同步。正式抓取前先连接并等待 Android 初始缓存回放基本稳定；完整日志照常保留启动时读取到的缓存。断线期间可能缺失数据，工具明确提示，重新连接另存一段。

串口通常被独占，使用本工具前需关闭 SuperCom 对同一端口的连接；Android Studio 不再是采集必需项。

## 7. 实施与验收

先在目标电脑和设备上验证双路后台采集，再接最小界面和文件导出。重点验证：Start/Stop 文件配对正确、备注能在抓取后修改、清屏不影响落盘、断线/磁盘错误可见、中文与同名标题不覆盖、长时间运行内存稳定。Android 额外验证：选择应用后 full 仍包含其他应用及系统日志，抓取文件仅保留匹配应用记录；目标应用启动、重启和多进程时过滤能正确跟随。

用已知字节数和序号的模拟输入核验保存内容（MCU 扣除工具添加的时间戳），验证空行、CRLF 跨块、半行、长行及 full/抓取时间戳一致，再进行实际设备连续采集与大文件导出测试。当前目录约 2.50 MiB 的人工片段不能代表全天数据量；容量和性能目标以实际持续采集速率确定。
