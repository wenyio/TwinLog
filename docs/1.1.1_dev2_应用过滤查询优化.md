# 1.1.1_dev2 应用过滤查询优化

日期：2026-11-20。基于 commit `a5784ca`，正式版本保持 `1.1.1`。

## 原因与修改

- 用户本次连接记录中出现多次 `context deadline exceeded`。旧逻辑每 500 毫秒触发查询，慢查询结束后可能立即再次查询；主查询、备用查询和重试共用 6 秒期限，首次命令卡满时备用查询没有剩余时间。设备超时根因仍未确定。
- 改为查询完成后等待：健康时 3 秒，连续失败后依次为 2、4、8 秒，之后维持 8 秒；成功后恢复 3 秒。保留现有进程启动、退出事件处理和周期校正。
- 单条命令独立超时 2 秒，整轮总期限 9 秒，包含两种 ps 命令及一次重试；限制命令管道退出等待时间。同一设备优先使用最近成功的查询方式，设备切换后不沿用其他设备的偏好。
- 错误保留命令、轮次、执行或解析阶段、耗时和超时原因；每次失败在连接事件中记录连续失败次数及退避间隔，恢复事件记录失败次数和持续时间。
- 通知详情显示不可用持续时间、最近成功时间、失败次数和重试间隔。正文说明预览和抓取可能存在缺口，恢复通知明确此前内容未自动补回。同一次故障关闭后不因重试重复弹出，新故障重新提示。
- 查询失败仍清空旧 PID，不放宽共享 UID 的归属判断；完整日志写入和缺口标记保留。不包含历史日志补回功能。

## 本次验证

- `go test ./...`、`go vet ./...`：通过。新增覆盖主查询超时后备用查询仍有独立预算、成功查询方式优先、取消后停止及保留失败链、退避和恢复状态。现有共享 UID、完整日志保存和缺口标记测试通过。
- `npm.cmd run build`、`npm.cmd run test:capture`：通过。新增覆盖缺口说明、关闭完整日志时不承诺保存、恢复通知及下一次故障重新提示。
- 测试进程使用工作区内 `.tools/go-build-cache` 和 `.tools/filter-query-test-temp`，避开默认缓存及临时目录访问问题。
- 未做真实 Android 设备负载、ADB 超时复现或应用重启实机验证；不能据此认定设备超时根因已消除。设备缺少启动事件时，新进程识别可能等待下一轮校正；失败退避期间恢复检测也会延后。
- `build.ps1 -OutputName TwinLog_1.1.1_dev2.exe`：通过，包含 Go 测试、前端编译和 Wails Windows 构建。产物：`build/bin/TwinLog_1.1.1_dev2.exe`。运行中的 dev1 未被覆盖或停止。
