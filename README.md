# TwinLog · 双路日志助手

Windows 桌面工具，可单独或同时保存 MCU 串口和 Android logcat。Go + Wails + React + TypeScript，无数据库。

支持双路持续日志、按标题抓取、普通文本备注、Android 应用过滤、历史预览与 ZIP 导出，采用 [MIT 协议](LICENSE)。版本见界面及 `frontend/package.json`。

## 使用

标题栏最小化按钮左侧提供图标形式的“置顶”和“小窗”入口，悬停查看提示。小窗与完整窗口使用同一个抓取面板，连接、标题、备注、结果标记和操作限制保持一致；小窗仍可通过“设备连接”页配置和连接设备。小窗进入宽度与主窗口右侧面板一致（通常 308px，窄主窗口为 282px），忽略旧的宽度记忆；默认高度 620px，最小 282×560。进入时靠当前屏幕工作区右侧放置，留约 12px 边距并避开任务栏，默认置顶，展开后恢复之前的主窗口尺寸、位置、最大化和置顶状态。开始、停止或新建抓取不会改变窗口尺寸，结果区增减由备注区吸收剩余高度；备注默认显示，内容超出时在框内滚动。可拖动窗口边缘或备注右下角调整小窗宽高，聚焦右下角手柄后也可用方向键微调；记住上次小窗高度，每次进入时宽度重新匹配主窗口右侧面板。切换前会保存待写入标题和备注，失败则保留当前模式并提示。关闭按钮仍执行原有的保存和退出确认流程。

运行 build/bin/TwinLog.exe。选择保存目录和至少一路设备，点击“连接设备”即可连接，每次连接创建独立目录。连接默认按时间显示，右键连接行可补名或改名；重连不会追加或覆盖之前的完整日志。只选串口或只选 Android 时，中间只显示对应的日志窗；两路都选时默认上下分屏；布局按钮依次为“上下 / 左右 / MCU / Android”，已有有效布局偏好继续保留。可用下拉框中的“不连接串口”或“不连接 Android”清除该路选择。如需只抓某个 Android 应用，点击“加载应用”，输入/选择包名；也可先在手机打开目标应用，再点击包名框右侧的准星“获取前台应用”，自动选择并应用过滤。每次点击只获取一次，之后手机切换应用不会自动更改选择；抓取中和查看历史时不可切换。未连接采集时也可查询已选择的 Android 设备。查询失败保留原选择，锁屏或无法确定前台时请解锁并打开目标应用后重试。留空表示全部应用。

启动时串口枚举立即开始，读取配置后并行查询历史记录和 Android 设备，各项完成后分别显示；历史目录读取慢或 ADB 响应慢时，其他列表仍可正常加载。

串口波特率默认 `115200`，预置 `9600`、`19200`、`115200`、`460800`、`1500000`。需要其他值时，在波特率下拉框选择“新增波特率…”，保存后会选中该值，重启后仍可选择。实际支持的波特率取决于串口硬件和驱动。

标题和备注均可留空，点击“开始抓取”即可开始，未填写标题时显示“未命名”。抓取期间中间只预览写入当前记录的内容，不混入连接预览里的旧内容。抓取中可直接修改标题及备注，并自动保存；已保存记录的标题以文本显示，通过右键“重命名记录”或右侧“重命名”修改，备注仍自动保存。抓取中，顶部始终提供“停止并保存”；“新建抓取”固定在抓取面板顶部，停止后或查看历史时点击它，进入独立的标题和备注草稿，再点击“开始抓取”开始下一条；未开始的草稿在切换历史记录后仍保留。未连接时也可先填写草稿，再到“设备连接”连接设备。点击左侧记录，中间仅显示该条记录实际抓取的日志来源；历史预览只读文件末尾，点击“打开记录目录”可用文本工具查看全文。“返回实时”恢复当前设备的实时布局和连接预览。

“设备连接 → 更多设置 → 预览行数”同时控制实时和历史预览，可选 1000、2000（默认）、5000 或 10000 行。提高设置后，实时预览从新日志开始积累，历史记录重新打开后生效；每窗仍有独立的大小上限。

顶部工具栏只显示“历史日志”或“完整日志”和“返回实时”；记录标题在左侧列表与右侧详情查看，也可悬停顶部“历史日志”查看完整标题，悬停“完整日志”查看连接时间。日志截断提示显示在对应日志窗标题栏，悬停可查看全文打开方式，不再额外占用正文高度。错误、过滤警告和操作结果显示为右下角悬浮通知，长消息可展开详情：普通成功提示约 3 秒后消失，归档提示保留约 8 秒并提供撤销，鼠标悬停或键盘焦点位于通知内时暂停消失。错误可手动关闭，过滤警告恢复后自动移除；关闭过滤警告后，本轮重试不重复弹出。

`Ctrl+F` 搜当前可见日志窗的预览；双窗时搜最近点击或聚焦的一窗，也可点击该窗的放大镜。`Enter` / `Shift+Enter` 跳到下一个 / 上一个，`Esc` 关闭搜索。实时查找会暂停预览，关闭搜索仍保留定位，点击“回到最新”才恢复跟随。实时窗的橡皮擦只清空预览，不删除已保存的日志；历史窗不提供清空。

“设备连接 → 更多设置”中的“保存完整日志”默认开启，未连接时可修改。开启时从连接到断开持续写 `full`，不受手动抓取开始或停止影响；关闭时仍可实时预览，但只有手动抓取期间的日志会保存。不会删除已有的完整日志。

左侧按时间列出连接，优先显示名称；展开后查看完整日志和抓取记录。转圈显示在正在写入的日志行，折叠时移到连接行。右键连接、完整日志或抓取记录行可打开对应菜单，也支持聚焦行后按 `Shift+F10` 或菜单键，用方向键选择、`Esc` 关闭；右键不会切换正在查看的日志或改变批量选择。点击正在写入的“完整日志”会返回实时预览，不读取磁盘快照；已在实时页时不会清屏或改变滚动位置。Android 实时预览仍受应用过滤影响，磁盘上的完整日志不受影响。手动抓取期间保留当前抓取画面，不切换。点击历史记录或已断开的连接的完整日志可预览文件末尾，右键菜单可打开目录或单独导出。须断开对应连接后才能导出其完整日志。

列表向上滚动时，当前分组的连接标题与“完整日志”一起吸附在列表顶部；下一组滚到顶部时自动接替。折叠连接后隐藏完整日志与记录；没有完整日志的连接仅吸附连接标题。

左侧默认隐藏复选框和批量操作区，点击“批量管理”后显示，点击“完成”退出并清空选择。只有记录可以勾选。“全选记录”包含当前列表中折叠连接的记录；切换“当前 / 已归档”会清空选择，隐藏列表中的记录不参与批量操作。选中后可在底部批量导出 ZIP 或删除，抓取期间的批量导出限制保持不变。只导出一条记录时，ZIP 默认按最新标题命名；没有可用标题时沿用 `TwinLog_导出时间.zip`。导出记录时可附带对应已结束连接的完整日志，每次连接只打包一份；没有可用完整日志的记录仍可单独导出。ZIP 中的记录目录按原抓取时间和最新标题命名，格式为 `20261119_154942_标题`，时间保留到秒；标题为空时只用抓取时间，同一秒内重名时加 `_1`、`_2` 等序号。

鼠标悬浮连接行或单条抓取记录行时，行尾显示归档图标；鼠标点击后移出即隐藏，键盘聚焦时也可显示。右键菜单提供同一操作。连接归档包含其完整日志和所有抓取记录；单条记录归档仅收起该条，其他记录和完整日志仍留在当前列表。“已归档”按原连接分组显示归档内容，支持取消归档及“撤销”。整次连接归档后，须先取消连接归档，再恢复其中单条记录；记录自身的归档状态保留。归档前保存待写入字段，失败时不改变状态；当前抓取记录须先停止才能归档，连接须先断开才能整组归档，已完成记录可在连接期间单独归档。归档不移动或删除文件、不释放磁盘空间，重启后仍保留；当前查看的日志及备注保持显示。旧版无有效 `session.json` 的分组仍可归档单条记录，但不提供连接级归档。

删除记录只回收所选记录及备注；“删除完整日志”只回收本次连接的 `full`；“删除连接”回收本次连接的整个目录，不影响其他连接。正在进行的连接及其完整日志不可删除，抓取期间不可删除记录。确认默认选“否”，若 Windows 提示无法回收、只能永久删除，可选择取消。旧版 `.twinlog-trash` 内的记录仍可按 `restore.json` 手动还原。

停止抓取后，可在右侧“标记结果”选择 PASS、FAIL 或待判定，自动保存；旧记录默认待判定。左侧记录标题前用小空心圈、绿色对勾、红色叉号区分，悬停可查看完整结果。标记表达人工结论，与抓取中断、过滤缺口等采集状态独立。单条导出的默认 ZIP 文件名和包内记录目录会追加 `_PASS` 或 `_FAIL`，待判定不追加；批量导出的外层 ZIP 保持原命名，各记录目录保留自己的结果。标记保存在 `record.json`，不改写日志正文、日志文件名或本地记录目录，附带的完整日志不标记结果。

目录：开启完整日志时，`连接时间/full` 下为所选路的 `mcu.log` 和/或 `android.log`。抓取目录以 `抓取时间_初始标题` 命名，初始标题为空时只用抓取时间，里面保存所选路的同名日志，以及 `notes.txt` 和 `record.json`。改名不移动或重命名磁盘目录。`session.json` 保存连接信息和可选名称。

MCU 行首格式：[2026-11-17 11:56:10.745] 。空行同样有时间戳，跨块半行不重复加；时间是电脑收到行首数据的时间。同一接收块多行可同时间。串口正文按接收字节保存，预览按 UTF-8 解码，异常字符不改写文件。

## 运行条件与边界

- Windows 10/11，WebView2 Runtime，设备 USB/ADB 驱动与调试授权。用户不需要 Go 或 Node.js 运行环境。
- ADB 默认从 PATH 查找；可在“更多设置”选择 Android SDK 的 platform-tools/adb.exe。不会清空 logcat 或重启全局 adb server。
- 仅串口不要求 ADB，Android 单路不要求串口。两路都选时，若一路连接失败，不会自动降为单路，可在错误提示中选择仅连接另一路。已连接的设备断线会停止连接并保留已保存日志，手动重连产生新目录。
- 应用过滤：普通 UID 按 UID 筛选；共享 UID 按包名匹配主进程和“包名:子进程”并按 PID 筛选，每 500ms 刷新，结合 system_server 启停记录跟随重启。需要设备提供 UID 格式和 PID,NAME 进程表；应用未运行时显示等待。轮询/系统事件存在延迟，极短命进程或已退出且无法确认归属的历史 PID 可能不在应用文件中；开启完整日志时，full/android.log 不受过滤影响。非包名前缀的自定义进程、隔离 UID 进程及系统代应用输出暂不归入应用文件。
- 串口无法补回打开前的数据，Android 只能读取尚未覆盖且有权限访问的缓存。首次连接会回放缓存，正式 Start 前请等回放稳定。
- 实时预览只保留最近的日志；上滚会固定该窗内容，可滚回底部或点击“回到最新”恢复跟随。暂停和清屏不影响保存。开启完整日志时，抓取期间重叠的内容会写入 `full` 和当前抓取两处。
- 缓冲约每秒刷新，正常停止同步文件；异常终止或断电可能损失尾部。保存错误会明确报错停止。
- 历史验证记录见 `docs`，各记录仅代表对应版本和环境；真实设备兼容性、串口热插拔与 8 小时稳定性仍需验证。

## 开发与构建

在 Windows PowerShell 中构建。需要 Go（最低版本见 `go.mod`，本地开发使用 1.27.4）、Node.js 22 LTS/npm，以及 Wails 2.17.1。Wails 的 Windows 开发环境要求见 [官方文档](https://wails.io/docs/gettingstarted/installation)。

如果把 Go 解压到 `.tools/go`，开发和构建脚本会优先使用它，只修改当前进程 PATH；也可以使用 PATH 中的 Go。仓库不包含 Go、ADB、设备驱动或 WebView2 安装包。

首次准备（在仓库根目录运行）：

```powershell
if (Test-Path .tools/go/bin/go.exe) {
    $env:PATH = "$PWD/.tools/go/bin;" + $env:PATH
}
$env:PATH = "$env:USERPROFILE/go/bin;" + $env:PATH
go install github.com/wailsapp/wails/v2/cmd/wails@v2.17.1
Push-Location frontend
npm.cmd ci
npm.cmd run build
Pop-Location
```

先生成前端资源，是因为 Go 通过 `go:embed` 嵌入 `frontend/dist`；该目录不入库，新克隆后直接运行 `go test ./...` 会缺少资源。

```powershell
# 开发窗口
./dev.ps1

# 正式构建（先正常保存并退出运行中的 TwinLog）
./build.ps1

# 独立测试构建，不覆盖默认产物或正在运行的其他版本
./build.ps1 -OutputName TwinLog_1.3.0_dev1.exe
```

正式产物为 `build/bin/TwinLog.exe`。前端依赖以 `frontend/package-lock.json` 为准，使用 `npm.cmd ci` 安装；Go 和 Wails 依赖以 `go.mod`、`go.sum` 为准。官方 Go 源不通时，可对当前终端设置 `$env:GOPROXY = "https://goproxy.cn,direct"`。离线使用需提前准备 WebView2、ADB 及驱动。

## 自动验证

在首次准备完成、Go 已加入当前终端 PATH 后运行：

```powershell
go test ./...
go vet ./...
Push-Location frontend
npm.cmd run build
npm.cmd run test:startup
npm.cmd run test:capture
npm.cmd run test:scroll
npm.cmd run test:window
Pop-Location
```

界面测试在 Windows 使用已安装的 Microsoft Edge 和模拟 Wails 桥接，不连接设备。Go 实机测试默认跳过；需要手动设置 `TWINLOG_TEST_SERIAL`、`TWINLOG_TEST_ADB`（adb 路径）和 `TWINLOG_TEST_PACKAGE`（设备上的共享 UID 应用包名）后才会运行。实机测试只读查询进程和 logcat，不打开串口、不清空日志或重启应用。

`test:startup` 检查生产前端资源，运行前需先执行 `npm.cmd run build`；覆盖配置/历史/ADB 查询等待、查询失败隔离，以及启动扫描迟到时不能覆盖新目录的记录。

## 代码入口

- main.go、app.go：桌面窗口、桥接、选择目录、配置和退出保存。
- internal/capture：设备枚举、双路采集、时间戳、UID 过滤、文件保存和 ZIP。
- frontend/src：React 界面和类型化桥接。
- docs/需求方案.md：确认后的最小需求。

本项目仅在本地保存日志，不自动上传。
